## Migration notes and source-backed risks

### TypeScript 5.9 → 6 → 7

[TypeScript 6 release notes](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/) describe the bridge release: `rootDir` defaults to the config directory, `types` defaults to an empty list, inference changes can expose new errors, and legacy module/resolution/emit options are deprecated. Passing input filenames alongside an existing tsconfig now errors. Catlex already explicitly sets strict mode, `types: ["bun"]`, ESNext, Preserve, bundler resolution and noEmit; it does not use the deprecated baseUrl/node10/ES5 settings. Thus those defaults mostly reduce expected migration effort, but do not establish a clean typecheck. Its ESNext lib can gain declarations that conflict with runtime types.

[TypeScript 7 release notes](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) confirm the Go/native compiler is stable, changes template-literal inference to Unicode code points, revises JavaScript/JSDoc analysis, and provides no programmatic compiler API in 7.0. Compiler-API consumers need the TypeScript 6 compatibility route. Correction from implementation validation: Catlex builds with Bun but its scanner DOES use the TypeScript compiler API (`createSourceFile`, `forEachChild`, and AST guards). Keep `@typescript/typescript6` as a runtime dependency for that API while using TypeScript 7 as the development typechecker. Biome is the linter, so typescript-eslint is not an identified blocker. `allowJs: true` still makes JavaScript analysis differences worth checking. Native platform packages become part of installation; compiler platform availability and editor support are separate from Bun's application cross-compilation.

Registry confirms intermediate [typescript 6.0.3](https://registry.npmjs.org/typescript/6.0.3) exists, while [@typescript/typescript6 6.0.2](https://registry.npmjs.org/@typescript/typescript6/6.0.2) is a compatibility wrapper exposing `tsc6` and the older API, with `@typescript/old: npm:typescript@^6`. The TypeScript 6 diagnostic pass was completed. The permanent compatibility dependency is required by the scanner, independently of the TypeScript 7 typechecker. [Upstream native compiler differences](https://raw.githubusercontent.com/microsoft/typescript-go/main/CHANGES.md) supply further intentional JS/JSDoc/declaration differences.

Original evidence: before the upgrade, package scripts did not include a TypeScript typecheck; the implementation now adds and passes `bun run typecheck`. `bun run check` is Biome, and `bun build` transpiles/bundles. Neither proves TypeScript 7 acceptance; the implementation explicitly ran the installed compiler against tsconfig successfully.

### Ink 6 → 7 → 8 and React

[Ink 7 migration notes](https://github.com/vadimdemedes/ink/releases/tag/v7.0.0): Node 22+, React 19.2+, Backspace maps to `key.backspace` rather than `key.delete`, and plain Escape no longer sets `key.meta`. Catlex Confirm/MultiSelect use return/arrows/space/letters, so these changed keys are not identified direct blockers. Input parsing, paste and terminal teardown still warrant regression checks.

[Ink 8 migration notes](https://github.com/vadimdemedes/ink/releases/tag/v8.0.0): React 19.3+, numeric-only Box minWidth/maxWidth, generic stream types for render options and stream hooks (TTY-only fields no longer guaranteed), and dropping unrecognized terminal control sequences in useInput. Source search found no Box minWidth/maxWidth or useStd* consumers in catlex. Keep React and its types synchronized with Ink; reconciler 0.34.0 specifically peers on React ^19.3.0, tighter than Ink's own range. Do not force a reconciler upgrade underneath Ink 6.

[React 19.3 release](https://github.com/react/react/releases/tag/v19.3.0) is the official context for the renderer update. The target is registry stable 19.3.1, not a canary. Existing tests under tests/cli/ui exercise render output and input; rerun those and the full isolated suite when implementing. ink-testing-library 4's own published development setup used Ink 5/React 18, so permissive peer metadata alone is weak evidence for Ink 8 scheduling compatibility ([published manifest](https://registry.npmjs.org/ink-testing-library/4.0.0)).

### React DevTools 8

[Official DevTools changelog](https://raw.githubusercontent.com/facebook/react/main/packages/react-devtools/CHANGELOG.md): 8.0.0 enables the Suspense tab by default, removes Timeline profiler UI, and adds/changes inspection and connection behavior. These are primarily debugging UX changes rather than a documented breaking initialize/connect API migration for catlex. The published 8.0.0 manifest still depends on shell-quote ^1.6.1 and ws ^7; no new peer/engine requirement is declared. Absence of such metadata is not a support guarantee.

Local Ink 6 evidence: build/reconciler.js only dynamically imports its DevTools integration when `DEV === 'true'`; build/devtools.js imports the package default backend and calls initialize/connectToDevTools. No catlex source directly imports DevTools. This narrows routine runtime exposure but does not prove the package is absent from compiled artifacts: Bun can include dynamic imports, and development dependencies installed during compilation can affect bundling.

### Commander 15

[Official changelog](https://raw.githubusercontent.com/tj/commander.js/master/CHANGELOG.md): implementation becomes ESM-only, deprecated commander/esm.mjs disappears, Node baseline rises to 22.12, and defaults change when both positive and negative flags exist. Catlex already uses ESM and root commander imports. Its --no-config flags have no matching --config positive flag, so that specific paired-flag change is not an identified current blocker. ## Security assessment: affected dependency is not the same as demonstrated exploit

### Zod: GHSA-mrhx-c7xc-m3w5

[GitHub reviewed advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) classifies versions below 4.6.6 as affected and severity High. Locked 4.4.3 is affected. Dependency paths: catlex → zod directly; ai and @ai-sdk/openai (and SDK transitive packages) also consume Zod as a peer. One compatible root update can satisfy these peers.

The [maintainer fix](https://github.com/colinhacks/zod/commit/a0ebf97) specifically moves upper-bound checks ahead of element parsing for array/set/map schemas. Important qualification: the advisory prose refers to unbounded arrays, while the actual fix early-rejects collections **with declared size bounds**. It does not impose a universal cap. Catlex's translations and reviews arrays in src/core/translate/schema.ts and review-schema.ts have no .max()/.length(); they accept model/tool outputs, so large malformed tool input can still cost memory after the package upgrade. Prioritize upgrading and separately consider response/body/token limits plus schema bounds tied to requested items. Config schema has objects/records but no arrays; the ordinary offline locale-validation path is not demonstrated to invoke this specific collection failure mode. No exploit reproduction was run.

### shell-quote: GHSA-pqg4-j6r4-53mv

[Maintainer advisory](https://github.com/ljharb/shell-quote/security/advisories/GHSA-pqg4-j6r4-53mv): affected >=1.8.4 <1.11.0, fixed 1.11.0. Exploitation requires quote() processing a comment token followed by an attacker-controlled string with a line terminator and executing its output through a shell. The maintainer page labels it High; the [reviewed database entry](https://github.com/advisories/GHSA-pqg4-j6r4-53mv) labels it Critical, consistent with the reported audit. Record this source severity difference instead of treating the labels as identical.

Confirmed lock path: **catlex devDependency react-devtools-core 7.0.1 → shell-quote ^1.6.1 → locked 1.10.0**. Target [1.12.0](https://registry.npmjs.org/shell-quote/1.12.0) fits the parent's existing range; a targeted transitive refresh can fix the audited resolution without DevTools 8. DevTools 8 retains the same range, so merely changing its major does not prove remediation.

No direct shell-quote import or quote() use was found in catlex source. Inspection of the installed upstream artifacts found shell-quote code embedded in the **standalone** DevTools sourcemap, while the default export consumed by Ink is the **backend**. The standalone editor source imports parse(), not quote(), and spawns the editor with argument arrays on Unix. No path satisfying this advisory's quote/comment/line-terminator/shell preconditions was identified. This is a limited static exposure assessment, not proof of no vulnerabilities. The standalone bundle embeds an older implementation whose exact version was not established; refreshing node_modules/shell-quote does not rewrite prebundled upstream code. Keep that separate from the audited 1.10.0 lock entry. Default CLI exposure appears lower than the raw Critical label suggests, but patch the resolution promptly and validate bundled artifacts if distribution reachability needs a stronger claim.

### How to interpret transitive targets

- SDK target manifests pin provider 4.0.34 and provider-utils 5.0.71; ai also pins gateway 4.0.130. Let those follow the direct updates. provider-utils still pins @workflow/serde 4.1.0 and eventsource-parser ^3.0.8; gateway still pins @vercel/oidc 3.2.0. Therefore their registry latest majors (serde 5, parser 4, OIDC 4) are **not** proposed overrides. Sources: [provider-utils manifest](https://registry.npmjs.org/@ai-sdk/provider-utils/5.0.71), [gateway manifest](https://registry.npmjs.org/@ai-sdk/gateway/4.0.130).
- Ink 8 intentionally upgrades its ANSI/rendering tree: chalk ^6.0.1, ansi-styles ^7, cli-boxes ^4.0.1, cli-truncate ^6, wrap-ansi ^10.0.2, ansi-tokenize ^0.3.1, react-reconciler ^0.34.0. Width/emoji/truncation behavior can change terminal output even without JSX changes. Keep Yoga ~3.2.1, cli-cursor ^4 and signal-exit ^3 on the upstream-declared ranges rather than overriding every outdated utility. Source: [Ink 8 manifest](https://registry.npmjs.org/ink/8.0.0).
- DevTools 8 remains on ws ^7; the separate Ink 6 ws ^8 resolution is not interchangeable. Do not force ws 8 under DevTools just because it is registry latest. Source: [DevTools 8 manifest](https://registry.npmjs.org/react-devtools-core/8.0.0).
- Bun types still request @types/node `*` and now also undici-types `*`; exact lockfile retention matters. Latest Node types can describe APIs not implemented by the supported Bun version. Source: [bun-types manifest](https://registry.npmjs.org/bun-types/1.4.4).
- Biome's eight optional platform CLI packages all move to exactly 2.6.4 with the parent; TypeScript 7 adds 20 matching-version optional native platform packages. These are development/compiler install artifacts, not replacements for catlex's five Bun release executables. Sources: [Biome manifest](https://registry.npmjs.org/@biomejs/biome/2.6.4), [TypeScript manifest](https://registry.npmjs.org/typescript/7.0.2).
